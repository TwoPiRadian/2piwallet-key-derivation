# 2π Wallet — Key Derivation (Open Source)

This repository contains the **exact mnemonic-to-address derivation logic**
used by [2π Wallet](https://2piwallet.com), a self-custody crypto wallet
app for Android. It is published so anyone — testers, auditors, or the
simply curious — can verify how the app turns a seed phrase into
addresses and private keys, without having to trust a claim or decompile
an APK.

This is **not** the whole app. It contains no UI, no networking, no
secure storage, no API keys, and no business logic — just the pure
derivation functions, extracted from the real app source.

## What's here

| File | Mirrors (in the main app repo) | Used by |
|---|---|---|
| [`lib/src/evm_derivation.dart`](lib/src/evm_derivation.dart) | `lib/services/evm_wallet_service.dart` (`_deriveEthKeyFromMnemonic`) | Regular ("hot") wallet — Ethereum and every other EVM chain the app supports (BSC, Polygon, Avalanche, Fantom, Base — one address, many networks) |
| [`lib/src/btc_derivation.dart`](lib/src/btc_derivation.dart) | `lib/services/btc_wallet_service.dart` (`_deriveFromMnemonic`, `_bech32Encode`) | Regular ("hot") wallet — Bitcoin, derived from the **same** mnemonic as the EVM address above |
| [`lib/src/cold_wallet_derivation.dart`](lib/src/cold_wallet_derivation.dart) | `lib/services/cold_wallet_service.dart` | The offline **Cold Wallet Creator** — generates a 24-word mnemonic and derives both addresses from scratch, with no third-party crypto packages |

The code in this repo is copied from the app with only one change: the
Cold Wallet Creator's word-list loading. In the app it comes from a
Flutter asset bundle (`rootBundle`); here it's a plain `List<String>`
parameter so this code has zero Flutter dependency and runs as a normal
Dart script. Everything else — every function body, every constant, every
derivation path — is unchanged.

## Why two different implementations?

- **Hot wallet** (`evm_derivation.dart` / `btc_derivation.dart`) uses the
  standard, widely-audited `bip39`, `bip32`, `web3dart`, and
  `bitcoin_base` packages — the normal way to do this in Dart.
- **Cold Wallet Creator** (`cold_wallet_derivation.dart`) deliberately
  implements BIP-39 mnemonic generation, BIP-32 HD derivation,
  secp256k1 point math, Keccak-256, RIPEMD-160, and Bech32 **from
  scratch**, with no wallet-specific package dependencies (only
  `pointycastle` and `crypto` for primitives like SHA-256/HMAC). The idea
  is that someone generating a cold wallet to hold real value can read
  every step of how their keys are produced, end to end, in one file.

Both implementations derive from the same standards (BIP-32/39/44/84) and
produce addresses that interoperate with any other standard wallet
(MetaMask, Trust Wallet, Ledger, etc.).

## Where does the randomness come from?

`evm_derivation.dart` and `btc_derivation.dart` only **derive** an
address/key from a mnemonic you already have — they take a `mnemonic`
string as input and never generate one, so there's no entropy source in
those files to audit.

The hot wallet's mnemonic is generated by the `bip39` package's
`generateMnemonic()` (see `example/main.dart`). Its source
([bip39_base.dart](https://pub.dev/packages/bip39)) uses `Random.secure()`
internally:

```dart
Uint8List _randomBytes(int size) {
  final rng = Random.secure();
  ...
}
```

`cold_wallet_derivation.dart` calls `Random.secure()` directly and
visibly, since that file is deliberately dependency-free. Both paths end
up using the same cryptographically-secure RNG — one just does it inside
an external package, the other inline so it can be read without trusting
a dependency.

## Derivation paths

| Asset | Path | Standard |
|---|---|---|
| EVM (ETH, BSC, Polygon, Avalanche, Fantom, Base) | `m/44'/60'/0'/0/0` | BIP-44 |
| Bitcoin (native SegWit, `bc1q…`) | `m/84'/0'/0'/0/0` | BIP-84 |

The hot wallet uses a 12-word (128-bit entropy) mnemonic. The Cold Wallet
Creator uses a 24-word (256-bit entropy) mnemonic for extra margin on a
wallet meant to be generated once, offline, and stored long-term.

## Running it

```bash
dart pub get
dart test            # runs a known BIP-39 test vector + round-trip checks
dart run example/main.dart
```

`example/main.dart` generates a fresh hot-wallet mnemonic and a fresh
cold-wallet mnemonic, derives EVM + BTC addresses for both, and confirms
that re-deriving from a saved mnemonic reproduces identical addresses —
the same guarantee the app's "confirm your backup" screen relies on.

## What this does *not* cover

This repo does not include: secure storage/encryption of keys on-device,
the PIN/biometric gate in front of signing, transaction building/signing,
RPC/API calls, or any UI. Those live in the main app and are outside the
scope of what needed independent verification — this repo is specifically
about the one question that matters most for a wallet: *does my seed
phrase produce the addresses the app shows me, using standard, correct
derivation, with nothing else going on?*
